Recommendation without schema/job: make recovery an explicit one-shot continuation of an actually deferred generation response, rather than a side effect of every ordinary GET. Return an internal deferred marker in the generation payload, carry it only into the scheduled recovery refresh, and consume/clear it after recovery; ordinary polling and refresh after explicit Clear must stay read-only. Continue checking caller permission, session ACTIVE, autoqueue enabled, all courts busy and queue absence. Clear must cancel pending client recovery intent and sequence safely against an already in-flight recovery (an aborted fetch alone does not guarantee the server writer stopped). Retain a real DELETE->GET integration test and an in-flight recovery/clear ordering test. A plain query flag is intent, never authorization.
